# Case 022 — Layer 5 승인 게이트 실체화 — 승인 후 배포 파이프라인

**TL;DR.** PR이 검증을 통과한 후 사용자의 명시적 승인을 거쳐 배포로 이어지는 Layer 5 승인 게이트를 실체화함. 이를 통해 운영 배포 전 최종 가드를 구축하고 승인 이력을 체계적으로 관리함.

## 1. 무슨 일이 있었나 (사실)

- 현재 PR이 검증(Layer 4)을 통과하면 사용자의 명시적 승인 없이도 배포가 가능하거나, 승인 절차가 시스템적으로 강제되지 않음.
- `docs/PIPELINE_STATES.md`에는 `approved` 상태가 정의되어 있으나, 이를 검증하고 배포로 이어주는 Layer 5 게이트가 미구현 상태임.
- 운영 환경으로의 안전한 변경 도달을 위해 '승인 기록'을 남기고 배포를 트리거하는 로직이 필요함.

## 2. 어느 액터/레이어에서 발생했나
- Layer 5 (승인 게이트 + 배포) 미구현.

## 3. 오케스트레이터가 막거나 도울 수 있었는가
- Layer 5에서 사용자의 승인(라벨 또는 커멘트)을 확인한 후 배포를 트리거했다면, 원치 않는 시점의 운영 반영을 막을 수 있었음.

## 4. 반복 가능성
- 모든 운영 배포 시마다 발생.

## 5. 결정
- [x] (a) decided-implement: Layer 5 실체화 시작.
- [x] (a-1) GitHub PR의 승인 상태(라벨/리뷰)를 확인하는 API 구현.
- [x] (a-2) 승인 완료 시 배포 워크플로우를 트리거하거나 상태를 `approved`로 전이시키는 로직 추가.

## 7. 학습 (ChromaDB 인덱싱 대상)

배포 전 최종 가드인 Layer 5는 액터들의 합의가 운영에 반영되는 최종 관문이다. 기술적 검증(L4)만큼이나 책임 주체의 명시적 의사표시(L5)를 기록하고 강제하는 것이 DevOps 오케스트레이션의 핵심이다.
